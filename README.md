# Git History Visualizer

中央开发者球群展示累计代码改动，外围 24 小时时间环展示作者提交时刻。发光游标沿时间环顺时针推进，到达真实提交时刻时发射粒子；粒子沿弧线飞入作者球，吸收后累计量增加。

## 本地运行

推荐 Node.js 24（最低 22），并预先安装 Git。首次准备依赖（需要联网）：

```bash
npm run setup
```

该命令安装锁定的 npm 依赖，缺少 Chromium 时下载对应版本；macOS 缺少 FFmpeg 时通过已安装的 Homebrew 安装。其他系统需先安装 FFmpeg 和 ffprobe 并加入 PATH，Linux 还需准备 Chromium 所需系统库。Node.js、Git 和 Homebrew 由用户预先安装。准备完成后，以下操作使用本地依赖：

```bash
npm run studio
```

也可运行 `npm run setup -- --start`，准备后立即启动；追加 `--no-open` 可抑制 macOS 自动打开浏览器。普通 `npm run studio` 和视频导出均不会安装依赖。

服务就绪后，macOS 会自动打开默认浏览器。只启动服务、不打开浏览器时，运行 `npm run studio -- --no-open`；非 macOS 环境请手动打开终端显示的 HTTP 地址。默认地址为 http://127.0.0.1:4173，设置 `GIT_HISTORY_PORT` 可使用其他端口。不要直接通过 `file://` 打开 `studio.html`，页面会提示启动服务并禁用操作。

本地仓库支持手动输入绝对路径，也可点击按钮选择文件夹；路径可以包含中文和空格。输入非空本地路径或选择文件夹会清空远程 URL，目录选择取消或失败会保留当前输入。目标分支默认 `main`，也可手动指定其他分支。也支持远程 GitLab URL；私有仓库需要 Token，Token 不写入项目配置，本地分析不发送 Token。时区默认 `Asia/Shanghai`，作者显示人数默认 16，范围 1–32；超出人数按最终改动量汇总为“其他”。

服务仅监听 `127.0.0.1`，只开放播放页面、必要脚本和 `exports/` 下的 MP4；`.git`、`.cache` 及其他工程文件不可通过 HTTP 读取，允许的资源也不能通过符号链接指向其他文件。远程登录的 Token 仅传入 Git 子进程环境，由固定的 askpass 脚本读取，不生成含 Token 的临时文件，并禁用此次调用的 Git 凭据存储助手。请使用 Token 输入框，不要将凭据写入仓库 URL；Token 在登录期间仍可被有权限检查本机进程环境的程序读取。旧版本若被强制终止，可能留下 `.cache/repositories/*-askpass.sh`，升级后可删除这些旧文件。

已有历史时，Studio 默认收起仓库配置，生成成功后也会自动收起；通过顶部“仓库配置”可重新打开，输入内容会保留。宽屏在左侧展开配置，窄窗在视频上方展开。

播放、进度拖动、专注观看、全屏和导出集中在播放器工具栏。“专注观看”暂时隐藏配置与详情，退出后恢复原来的展开状态；“全屏”包含视频和操作栏，可再次点击或按 Esc 退出。项目概览保留总变更、最终存留、提交数和开发者数，未纳入事件和统计口径在“统计详情”中展开。导出进度及下载链接显示在工具栏下方，与配置区的生成提示分别显示。

点击开发者球可查看当前已吸收的新增、删除、改动量、占比及最终存留。拖动时间轴可任意回放。预览与导出 MP4 使用同一数据、配置和渲染函数。

播放结束或拖到末尾后，再次点击“播放”会从头重播；中途暂停后继续播放会保留当前位置。

## 统计口径

- 只统计目标分支 HEAD 可达的非合并提交，按 SHA 去重；目标分支不必叫 main。
- 改动量 = 新增行数 + 删除行数，不等于贡献质量或仍存活的代码量。二进制文件不计行数。
- 沿用源码、测试和配置统计，排除 lockfile、vendor、构建产物、覆盖率目录及 node_modules。
- 时间轴按 `authoredAt` 排列，相同作者时间按提交者时间和 SHA 排列。按间隔平方根压缩空闲时段，末尾预留粒子吸收时间。
- 00 点下、06 点左、12 点上、18 点右；分钟和秒连续映射，统一按配置时区解释。作者时间来自 Git 元数据，可能与实际开发时间不同。
- merge commit 不重复累计，也不单独归属合并冲突解决产生的改动。不计算或展示合并组／MR 详情。
- squash 只能展示仓库保留的提交和作者，不推测原始作者；按小写邮箱识别作者，不自动合并不同邮箱。
- 开发者球面积共用一个比例尺；小贡献的姓名有独立文字空间，零改动作者显示极小轮廓。吸收时有短暂脉冲，静止后面积恢复准确比例。
- 颜色按作者标识稳定生成，配置人数改变会重新选择展示对象。已有缓存里的作者位置优先保留；需要更多空间时统一缩小球的尺度，仍无法容纳时重新布局。
- 视觉粒子仅合并同一关联后的开发者、相同 `authoredAt`、相同播放时刻的提交；其他提交分别从精确时刻发射，数据仍逐条累计。
- 游标映射完整提交时刻，右下角显示历史日期，跨午夜继续顺时针；无提交的完整日期在午夜折叠，并显示“跳过 N 个无提交日”。两端保留时段按真实时长分配播放时间，日期边界按配置时区计算。首次提交前及最后提交后游标停留，空历史不显示游标。

## 缓存与导出

manifest v2 保存去重 commit、作者时间和布局位置。v1 缓存首次重新生成；同仓库、分支、HEAD、排除规则及统计格式命中缓存时，直接复用提交和项目总量，不重新读取完整日志。调整时长、时区、显示人数与账号关联会重新生成展示配置、时间轴和布局。存留缓存缺失或算法版本过期时只重算存留。新增历史只读取新提交行数，并重新排列完整时间轴。旧 HEAD 不再可达或排除规则改变时重新分析。

Studio 和默认 CLI 分析结果写入 `.cache/current/manifest.json` 及 `.js`，仓库缓存写入 `.cache/manifests/`；这些目录不纳入 Git。`data/manifest.*` 保存随源码发布的 DeepSeek Harness 示例。Studio 优先载入本地运行结果，没有时使用随源码发布的数据。分析自己的仓库不会改写公开示例。manifest 包含姓名、邮箱、提交说明和仓库路径，分享前请检查这些信息。

示例来自 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness) 的 `master` 分支，固定在提交 [`5badb15009ae1756c3afe0ae0cef1faafc290ccc`](https://github.com/deepseek-ai/deepseek-harness/commit/5badb15009ae1756c3afe0ae0cef1faafc290ccc)，不随上游自动更新。保留公开 Git 历史中的作者姓名、邮箱和提交说明，移除本机仓库路径；不包含仓库源码。示例有 12,469 个非合并提交、68 个邮箱身份，默认播放 60 秒，显示前 16 个作者，其余汇总为“其他”。首次启动即可播放，无需克隆 DSH 或重新分析。

Studio 点击“导出 MP4”，文件写入 `exports/`。使用本地 Playwright Chromium 逐帧绘制，再通过 PNG 管道交给本地 FFmpeg，生成 1920×1080、30 fps、H.264 MP4。预览与成片共用 Canvas 绘制函数；导出固定当前页面在点击开始时传入的 manifest 快照，其他页面生成历史不影响本次导出，最后一帧呈现完整统计。显示人数和时区在“生成可视化”时生效。

Studio 显示准备状态、已处理帧数与百分比；到 100% 后等待编码完成，再提供下载链接。`POST /api/export` 默认仍返回 JSON，携带 `Accept: application/x-ndjson` 时按行推送 `start`、`progress`（`frame`、`total`）、`complete`（`file`）或 `error`（`error`）。进度最多每 250 毫秒推送一次，首帧和末帧必推送。请求校验失败或已有导出任务时仍返回 JSON 错误；流中断且未收到完成事件时页面提示失败。

导出页面只允许访问其独立的本地服务，外网请求会被阻止并使导出失败；无 CDN、遥测或运行时安装。Chromium 与 FFmpeg 缺失时显示中文错误。依赖准备完成后，本地仓库分析、预览与导出可断网使用；远程仓库克隆或更新仍需联网。同一时间只运行一个导出任务，失败会清理进程和不完整视频。

```bash
npm run analyze -- /absolute/path/to/repository main
npm test
npm run check
```

也可直接导出已保存的数据（无需启动界面）：

```bash
npm run render -- .cache/current/manifest.json exports/history.mp4
```

`npm run check` 包括历史统计测试和本地浏览器导出集成测试，因此执行前也需要准备 Chromium 与 FFmpeg。缺少依赖时测试失败，不自动下载。

依赖安装后运行 `npm run licenses`，根据 `package-lock.json` 和本地安装包生成 `LICENSES_THIRD_PARTY.md`，包含直接及传递 npm 依赖的许可证标识、完整许可证文本和 NOTICE。安装版本不匹配或声明缺失时失败，保留上次生成结果并提示人工核查。该清单不代替项目自身的 LICENSE，也不覆盖外部安装的 Git、Chromium 和 FFmpeg。

## 账号关联与动效

账号关联列表保留所有原始邮箱账号。默认每个账号都是主账号：“关联到”展开其他主账号供选择；将主账号关联到另一个主账号会合并整组。“解除关联”仅拆出当前关联账号；“设为主账号”保留整组并切换其主账号。配置后点击“生成可视化”生效并写入仓库缓存及 manifest；旧 manifest 无配置时仍按独立账号展示。

原始提交、SHA、作者邮箱与时间不变，展示按主账号汇总新增、删除、改动量和提交数，球与粒子统一使用主账号颜色、姓名。显示人数按合并后的开发者数量选择，“其他”人数也是合并后的数量。

粒子半径使用 `0.5 × sqrt(新增＋删除行数)`，正常范围内面积正比于改动量；半径限制为 1.5–18 像素，零改动事件保留最小标记，极端大提交不会遮挡整个画面。作者球使用稳定初始布局＋确定性受力运动：近距离排斥、远距离弱吸引，整群按质量加权质心回中；不回到各自初始位置。粒子冲量按半径平方增加，零改动无冲量，同刻度冲量先合并再限幅。球增长会推开邻居，质量固定在 1–2，阻尼让撞击运动逐渐衰减，速度与中央区域边界都有约束。

`src/motion.js` 以固定 60 Hz 预计算位置轨迹，渲染时线性插值；作者在首次吸收刻度加入模拟。三次贝塞尔粒子路径与局部涟漪使用吸收时刻的球边缘，末端切线与撞击方向一致。Studio、点击命中、直接跳转和 MP4 使用同一轨迹，不依赖显示帧率或播放顺序。轨迹只缓存于 manifest 对象对应的内存中，不写入 Git 分析缓存；生成新 manifest 后重新计算。首版不引入物理引擎或 Worker。内部参数集中于 `MOTION`，保持当前界面配置。

## 双层球与最终存留

外圈面积表示截至播放时刻累计新增＋删除，内芯面积表示已播放提交中最终存留到目标分支 HEAD 的行数；两层使用同一面积尺度，并在粒子吸收后以 0.35 秒过渡增长。这是回看最终版本后的存留，不是历史当天的代码存量，也不代表贡献质量。粒子大小、冲量、质量和受力半径仍按改动量计算。

分析先固定 HEAD，再对排除规则允许的文本文件执行 Git blame（最多 4 个并发），按提交 SHA 汇总最后修改归属，包含空行和注释，不启用跨文件复制追踪或忽略空白修改。完整文件重命名由 Git 默认追踪。同一提交、原始文件路径和原始行号只计一次贡献存留；分支改名后保留多份文件等情况产生的重复行计入完整总量，多出的部分列为“未纳入贡献事件”。合并冲突解决、来源为历史排除文件或无法映射到贡献事件的行单列为“未纳入贡献事件”。完整存留总量＝贡献事件存留之和＋未纳入量，详情占比使用完整总量作分母。

manifest 保持版本 2，提交和原始作者新增 `retainedLines`；`retention` 记录统计版本、固定 HEAD、排除规则键、完整总量、已映射量和未映射量。账号关联只影响展示汇总。HEAD、排除规则或算法版本变化时重算最终归属，早期提交的存留可随新分析减少；仅更改展示配置会复用。旧 manifest 仍能播放，存留显示“未分析”，需重新生成。分析失败不替换上次结果。`analysis.retentionMs` 与 `retentionCacheHit` 用于确认耗时和缓存复用。

Git 行数统计采用 NUL 分隔格式，保证含中文、制表符和换行的文件名不破坏统计；旧格式的改动量缓存首次升级时重建，账号关联和初始布局保留。

作者球姓名下播放时仅显示改动数，播放结束后追加括号中的最终存留数，如 `12万（3万）`；内芯与右上角存留统计始终保留。姓名与数字使用两档固定字号，不按文字长度缩放，预览和导出末帧共用这一规则。

## 贡献

- 小修复可直接提交 PR，较大的功能先用 Issue 说明使用场景和最小方案。
- 描述问题时提供环境版本、复现步骤、预期与实际结果，优先用合成仓库复现。
- 核心模块：`scripts/analyze-history.mjs` 分析改动，`scripts/retention.mjs` 分析最终存留，`src/visualizer.js` 绘制，`src/motion.js` 计算运动，`src/studio.js` 管理交互。
- 改动统计或时间轴时补回归测试，保持预览与导出的确定性一致，并运行 `npm run check`。
- 修改导出时额外验证短 MP4 的解码、时长和最终累计量；现有集成测试覆盖这些检查。
- 依赖变化后运行 `npm run licenses` 并提交生成结果；CI 会检查声明与依赖是否同步。
- 不提交真实私有仓库 manifest、Token、缓存、视频或本机绝对路径。
- 提交信息使用中文，PR 说明问题、改动和验证结果；视觉改动附截图。
- 发布前通过检查、审查示例数据、创建版本标签，并在 Release notes 记录用户可见变化。
